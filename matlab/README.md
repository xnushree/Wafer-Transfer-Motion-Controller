# MATLAB / Simulink models

These are the Simulink versions of the R-θ-Z wafer-transfer robot, built in
MATLAB R2024b. They use the same decoupled model, parameters and controller
timing as the Python code, and the Python cross-check
([simulation/simulink_validation.py](../simulation/simulink_validation.py)) shows the two agree to about
5×10⁻¹³ mm.

This folder is a snapshot of a separate MATLAB project that I keep outside
Git on purpose. It is refreshed with [sync_from_project.py](sync_from_project.py).

## Contents

- [models/](models) holds the Simulink models:
  [r_axis_plant](models/r_axis_plant.slx),
  [r_axis_pid](models/r_axis_pid.slx),
  [r_axis_pid_ff](models/r_axis_pid_ff.slx),
  [r_axis_pid_ff_traj](models/r_axis_pid_ff_traj.slx),
  [theta_axis_model](models/theta_axis_model.slx),
  [z_axis_model](models/z_axis_model.slx) and
  [robot_3axis](models/robot_3axis.slx).
- [scripts/](scripts) holds [parameters.m](scripts/parameters.m), which defines
  every value used, along with the model builders (build_*.m, add_*.m), the studies (run_*.m), the checks
  (test_*.m, [verify_axis_plant.m](scripts/verify_axis_plant.m)) and
  [export_validation_data.m](scripts/export_validation_data.m).
- [results/](results) holds the plots and CSV tables the scripts produce.

The models are generated by the build_*.m scripts, so they can always be
rebuilt from code. Each axis loop has a quintic trajectory block, a discrete
PID (backward Euler, 2 ms sample time), optional feedforward and gravity
compensation, actuator limits with anti-windup, a step disturbance and
sensor noise. The plant is solved with the fixed-step ode4 solver.

## Running

Open MATLAB in this folder (or anywhere else) and run a script by its path,
for example:

```matlab
run('scripts/test_r_axis_plant.m')          % plant vs analytical solution: PASS
run('scripts/run_robot_3axis.m')            % 3-axis move, joint + Cartesian error
run('scripts/run_controller_comparison.m')  % 4 controllers x 2 plants, disturbance + noise
run('scripts/export_validation_data.m')     % CSVs for the Python cross-check
```

The scripts find models/ and results/ relative to their own location.

## Studies

[test_r_axis_plant.m](scripts/test_r_axis_plant.m) checks the open-loop plant against the analytical
solution; they agree to about 1e-14 m. [run_r_axis_comparison.m](scripts/run_r_axis_comparison.m),
[run_theta_axis.m](scripts/run_theta_axis.m) and [run_z_axis.m](scripts/run_z_axis.m) compare PID with PID + FF on each axis.
[run_saturation_study.m](scripts/run_saturation_study.m) and
[run_antiwindup_demo.m](scripts/run_antiwindup_demo.m) look at actuator limits and
integrator anti-windup, and
[run_disturbance_noise_study.m](scripts/run_disturbance_noise_study.m) at step
disturbances and sensor noise.
[run_controller_comparison.m](scripts/run_controller_comparison.m) compares PID,
PID + FF, a retuned PID + FF and the retuned version with payload
feedforward, on both the nominal plant and one with 20% more mass.

These are results from simulating this model, not measurements of a real
robot.
